# Інструкція з розгортання дипломного проєкту

**Тема:** Інформаційна система виявлення джерел розповсюдження дезінформації та неавтентичної поведінки чатботів (збір даних, аналітика Tier 1 + LLM, веб-інтерфейс).

**Стек:** Next.js (фронтенд) + FastAPI (API-gateway) + Python workers (collector, analytics) + **Apache Kafka** + **Redis** + Zookeeper. Усе розгортається через **Docker Compose**.

**Репозиторій:** https://github.com/slav41k/diploma

**Що потрібно на комп’ютері:** Docker Desktop (macOS / Windows / Linux), Git, вільні порти `3000`, `8000`, `9092`, `6379`, `2181`, рекомендовано ≥ 8 ГБ RAM для Docker. Опційно — обліковий запис Telegram і ключі API з [my.telegram.org/apps](https://my.telegram.org/apps); для блоку LLM — один із ключів Groq / Google Gemini / OpenAI (див. `.env.example`).

---

## 1. Запуск проєкту — три команди

```bash
cd /шлях/до/папки/diploma
cp .env.example .env
docker compose up -d --build
```

Перша команда `docker compose up -d --build` виконує одразу все:

1. Збирає образи **api**, **collector**, **analytics** (Python 3.12 + залежності з `backend/requirements.txt`).
2. Збирає образ **web** (Next.js).
3. Піднімає **Zookeeper**, **Kafka**, **Redis**.
4. Запускає сім контейнерів у фоні (`-d`).

**Перший запуск** може тривати **5–15 хвилин** (завантаження базових образів і збірка Python/Node). Наступні запуски — значно швидше.

Після старту відкрийте у браузері:

**http://localhost:3000**

Додатково (за потреби): документація API — http://localhost:8000/docs , перевірка gateway — http://localhost:8000/health .

Перевірка контейнерів: `docker compose ps` — усі сервіси у стані `running`; **kafka** — `healthy` (може зайняти до ~1 хв після старту).

## 1.1. Як перевірити роботу без жодних особистих ключів

Після `cp .env.example .env` **не обов’язково** заповнювати Telegram чи LLM — систему можна перевірити так:

**Новинний портал (реальний парсинг статті)**

1. Відкрити http://localhost:3000
2. Обрати **«Новинний портал»**
3. Вставити **пряме посилання на статтю** (HTML-сторінка з текстом, не головна сайту)
4. Натиснути запуск аналізу

Збір виконується через **newspaper3k** (без API-ключів). Далі спрацьовують Random Forest (Tier 1), правила **чорного списку** та **тригер-фраз** (файли в `backend/app/data/`), за наявності ключа — блок LLM.

**Інші платформи (демонстраційний mock-збір)**

Для **Twitter / X, Reddit, Instagram, Facebook** у поточній версії прототипу використовується **синтетичний mock-збір** (тестові повідомлення без звернення до API соцмереж). Це дозволяє показати повний ланцюг **Kafka → collector → analytics → UI** без реєстрації в зовнішніх сервісах.

1. Обрати платформу (наприклад Twitter)
2. Вказати довільний `target` (наприклад `test_topic`)
3. Запустити аналіз — через кілька секунд з’явиться результат з mock-коментарями та вердиктами моделей

> **Важливо:** mock-дані потрібні лише для демонстрації архітектури; для дипломної теми основне реальне джерело — **Telegram** (див. нижче).

### Опціонально: за кілька хвилин додати Telegram

1. На https://my.telegram.org/apps створити застосунок, скопіювати **api_id** та **api_hash** у `.env`:

```env
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=ваш_api_hash
```

2. Згенерувати рядок сесії (один раз, локально на машині з Python 3.9+):

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/telegram_session.py
```

Скрипт запитає номер телефону та код з SMS (за потреби — пароль 2FA). Після успіху в кореневий `.env` буде записано `TELEGRAM_SESSION_STRING=...`.

3. Перезапустити collector: `docker compose up -d --build collector`

4. У веб-інтерфейсі: **Telegram** → посилання на канал (`https://t.me/імʼя_каналу` або `@channel`) → кількість останніх постів для перевірки коментарів (1–50).

### Опціонально: ключі для LLM (Tier 2)

У `.env.example` наведено змінні. Достатньо **одного** ключа:

```env
LLM_PROVIDER=auto
GROQ_API_KEY=...
# або GOOGLE_API_KEY=...  або OPENAI_API_KEY=...
```

Після зміни `.env`: `docker compose up -d --build analytics`

Без ключа аналіз **завершується**, але блок детального JSON-пояснення LLM може бути обмежений або з повідомленням про відсутність ключа.

## 2. Які джерела даних реально працюють і чому

**Новинний портал** — працює без ключів (парсинг статті за URL через newspaper3k).

**Twitter / X, Reddit, Instagram, Facebook** — у прототипі **mock-збір** для демонстрації пайплайну; реальні API соцмереж не підключені.

**Telegram** — **основне реальне джерело** дипломної теми; потребує `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` і `TELEGRAM_SESSION_STRING` (див. розділ 1.1).

Архітектура збору й аналізу:

```
Браузер → web:3000 → api:8000 → Kafka (analysis_requests)
                              ↓
                         collector-worker → Kafka (raw_data)
                              ↓
                         analytics-worker → Redis (результат за job_id)
                              ↑
                         web поллить GET /api/v1/analysis/{job_id}/result
```

Контейнери: **web** (інтерфейс), **api** (запити в Kafka), **collector-worker** (збір), **analytics-worker** (RF, blacklist, тригер-фрази, LLM → Redis), **kafka** + **zookeeper** (черга), **redis-cache** (результати для UI).

Конфігурації threat intelligence (без перебілду образу analytics): `backend/app/data/blacklist.json`, `word_triggers.json`, `reference_narratives.json`.

## 3. Як користуватись інтерфейсом

1. Відкрити **http://localhost:3000**
2. Обрати платформу (Telegram, Twitter, Reddit, Instagram, Facebook або новинний портал)
3. Заповнити параметри (URL каналу / статті, кількість постів або повідомлень)
4. Натиснути запуск аналізу — інтерфейс очікує результат (поллінг)
5. Переглянути:
   - рівень загрози (LLM, якщо налаштовано);
   - список користувачів / записів із вердиктом (🟢 / 🟡 / 🔴);
   - вік акаунта (синтетична оцінка в MVP);
   - причини червоного статусу (чорний список або тригер-фрази);
   - детальний JSON LLM (розгорнутий блок).

## 4. Зупинка та типові проблеми

**Зупинити проєкт:** `docker compose down`

**Kafka не стартує (помилка `NodeExists`):**

```bash
docker compose down -v
docker compose up -d --build
```

> Увага: `-v` видаляє дані черги Kafka; для демонстрації це нормально.

**Логи:** `docker compose logs -f api` , `collector` , `analytics`

**Telegram не збирає коментарі:** перевірте `TELEGRAM_*` у `.env`, перезапустіть `collector`, переконайтесь, що в каналі увімкнені коментарі (прив’язана група обговорення).

### Опціонально: ML-звіти для пояснювальної записки

Оцінка моделей на відкритому датасеті (ROC, confusion matrix, F1) — **окремий** скрипт, не потрібен для роботи веб-прототипу:

```bash
cd backend
pip install -r requirements.txt
python scripts/ml_evaluation_report.py
```

Результати: `backend/reports/ml_eval/`. Опис методики: `backend/docs/DATASETS_AND_ML.md`.
